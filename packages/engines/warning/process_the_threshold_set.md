# Process: The Threshold Set

## Taxonomy

[The Issuing](process_issuing_warning.md)

## Owner

- Project: khai
- Engine: warning

## Initiated by

A line is drawn where the signal starts firing.
Above this reading, warn. Below it, do not. The line is a number and it was chosen.

## Direction

Toward a system that cannot be right in both directions at once.
Every threshold trades misses against false alarms, and the trade is fixed: moving the line to catch more of one produces more of the other. No amount of care removes it, because it is a property of deciding under uncertainty rather than a defect in the instrument.
So the only real question is which error the setter would rather live with, and that is a question about consequences rather than about signals.

## Lever

The rigour of the setting against what the setting cannot resolve.
The carrying force is that the choice is made responsibly far more often than not, with the asymmetry of harms genuinely considered -- a missed cardiac arrest is worse than an unnecessary check, and thresholds are set accordingly, which is the correct reasoning; the resistance is that setting the line to be safe guarantees a high false-alarm rate as an arithmetic consequence, so the very care that makes the system safe is what makes it cry wolf, and the two cannot be separated by any adjustment.
The Threshold Set buys sensitivity with noise, at a rate it does not get to choose.

## Echo

A rate of being wrong, fixed in advance.
It shows the domain's central constraint at the point where somebody accepts it.
The Threshold Set is dated from installation and is defended by whoever chose it.

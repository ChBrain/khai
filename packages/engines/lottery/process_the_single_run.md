# Process: The Single Run

## Taxonomy

[The Drawing](process_drawing_lottery.md)

## Owner

- Project: khai
- Engine: lottery

## Initiated by

It happens once.
No best of three, no re-draw, no adjustment for a result that looks wrong.

## Direction

Toward a binding outcome produced by an unrepeatable event.
The single run is what makes a lottery a decision rather than a sample: repeated, it would produce a distribution and somebody would have to choose from it, which is the problem the lottery was solving.
So the result is binding precisely because it cannot be checked against what the mechanism would have done otherwise, and everybody agrees to that in advance.

## Lever

The necessity of finality against what finality forecloses.
The carrying force is that irrevocability is the source of the whole arrangement's authority: a re-drawable lottery is not a lottery but an invitation to lobby for a re-draw, everybody consented to the terms beforehand, and the sharpest thing that can be said for the outcome is that it was accepted before it was known; the resistance is that a single draw carries no information about itself -- a fair mechanism and a rigged one produce indistinguishable single results -- so the finality that gives the outcome its force is the same property that makes it unauditable from the result.
The Single Run is binding and tells nobody anything.

## Echo

An outcome that stands and cannot be examined.
It shows why trust in a lottery has to be established before the draw and never after it.
The Single Run is dated to the instant and is not revisited.

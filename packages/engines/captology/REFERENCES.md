# Captology: Reference

## Line of Work

Captology as **piece**: the object designed to shape behavior and form habits -- an
engineered reinforcement loop that conditions the user over time to return. The
domain does not model an honest confirmation, which usability owns (feedback that
tells the user the act took); nor a one-time conscription, which agency owns
(enlistment, a state entered once); nor a deception, which guile owns (a trick sprung
on the user); nor the user's own conditioning and craving, which the conditioning,
addiction, and habit engines own on a persona (the learning and the need as they run
in the user). It models the object built to hook: the piece-pole of behavioral
conditioning, the persuasive technology of the loop.

The spine is Fogg's captology and behavior model, Eyal's hook, and the intermittent
reinforcement beneath them. The engine takes the object's engineered loop four ways:
the cue that starts it (trigger), the action made easy (ability), the variable payoff
that keeps it turning (jackpot), and the investment that binds the next turn
(investment) -- so a piece can declare not only that it hooks but by which part of
the loop it does so.

## Restrictions

What the engine refuses to model, and to whom it delegates.

- **The honest confirmation (usability)**: Usability's feedback is a certain,
  informative response that closes the use-loop and serves the user. Captology's loop
  conditions -- the variable reward, the manufactured cue -- to serve the maker's
  engagement. Feedback informs the user; the hook trains them. Both read on the object's
  response, and split on whose end the loop serves.
- **The one-time conscription (agency)**: Agency's enlistment drafts the user
  structurally, once -- the turnstile makes you a payer the moment you pass. Captology
  conditions the user over time -- the loop grooves a habit across repeated use.
  Enlistment is a state entered; captology is a behavior trained.
- **The deception (guile)**: Guile deceives -- it creates a false belief, a trick
  sprung on the user; captology conditions -- an engineered reward loop, which can be
  perfectly transparent (a step-counter that forms an honest exercise habit is
  captology, with no deception). A dark pattern catches you; a hook trains you. They
  co-occur, but the mechanisms differ.
- **The user's own conditioning (the conditioning, addiction, and habit engines, on a
  persona)**: Those engines model the person -- the learning (`conditioning`), the
  craving (`addiction`), the automaticity (`habit`) as they run in the user. Captology
  is the _object_ built to manufacture them: the piece-pole of the same behavioral
  science, maker-absent and scaled. The slot machine's design is captology; the
  gambler's compulsion is addiction's. Same science, different type.
- **The facet is not engine content**: The engine declares the four facets exist; which
  one a given piece turns on lives on the piece, linked under its Load Bearing chapter.
  The engine refuses to fix a piece's hook for it.

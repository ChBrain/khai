# Piece: Trigger

## Taxonomy

[Captology](piece_captology.md), the facet this is a part of. Trigger models the cue the object plants to start the loop -- the notification, the badge, the buzz that calls the user back, ripening from an outer prompt the object sends into an inner itch the user comes to feel on their own. Fogg's prompt, Eyal's trigger (external to internal). It is distinct from ability (the ease of the act once the reach has started): the trigger is what starts the reach.

## Owner

- Project: khai
- Engine: captology

## Place

At every moment the object can reach the user -- the lock screen, the badge, the email, the push -- and eventually inside the user, at the idle second their own hand finds the object unprompted.

## Load Bearing

What the trigger holds up is the return itself; without a cue the loop never starts. Remove the object's triggers and the user comes back only when a real want brings them; the manufactured returns rest on the manufactured cue. Its deepest form needs no cue at all: the object has trained an internal trigger, so that boredom, loneliness, or anxiety sends the user to it on their own, and the object no longer has to call because the user now calls themselves.

## Apparent

What shows is a helpful reminder; what is built is a call engineered to interrupt and pull. Any one notification looks like service; the trigger is the systematic manufacture of occasions to return, and its success is the moment it disappears into the user's own reflex and no longer looks like the object's doing at all.

## Yearbook

The history of a trigger is the record of the interruptions it caused and the reflex it built -- the reaches for the object at every idle second, the phantom buzz felt when there was none. The object is dated from the itch it planted in the user's own hand.

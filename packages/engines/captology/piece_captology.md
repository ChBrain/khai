# Piece: Captology

## Taxonomy

The root of the captology engine. It models persuasive design: a form built to shape the user's behavior and form a habit -- an engineered loop that conditions the user over time to return, borne beneath the ordinary use. Fogg's captology (computers as persuasive technology, the Behavior Model), Eyal's hook. It is distinct from an honest confirmation, which usability owns (feedback that tells the user the act took, not a loop that hooks them); from a one-time conscription, which agency owns (enlistment drafts you structurally, once; captology conditions you over time); from a deception, which guile owns (a trick sprung on the user, not a reward that trains them); and from the user's own conditioning and craving, which the conditioning and addiction engines own on a persona (the learning and the need in the user, not the object built to manufacture them).

- Project: khai

## Place

At the loop's return points -- every place the user comes back to the object: the moment the cue lands, the payoff pays, the investment is asked. Captology lives wherever the object can turn a single use into the next one.

## Load Bearing

What captology holds up is the user's habit of returning -- the engagement, the daily check, the compulsive open. Remove the loop -- take away the variable payoff, the manufactured cue, the frictionless ease -- and the returning falls back to whatever real want remained; the object's hold rests on the conditioning, not the want. The hook is borne beneath the ordinary use, invisible until the user notices they cannot stop reaching for it, and it stands as long as the loop keeps turning.

## Apparent

Little of the loop shows as a loop; that is its cover. The object looks like an ordinary useful thing, and each single use looks freely chosen. The conditioning lives in the pattern across uses, not in any one of them -- the habit assembled from a thousand small returns that each felt like a choice. What is apparent is a tool used; what is borne is a user trained.

## Yearbook

The history of a hook is the record of the time it took -- the hours logged, the compulsions formed, the users who tried to quit and came back, the ones who deleted it to get free. Over a life of use the object's engagement is judged against the attention and the lives it consumed, and the hook is dated from the habit it built: not a tool the user picked up, but one that would not put them down.

# Instructions: Captology

How a Playwright wires the captology engine into a play. You wire by linking the
play's own content to the engine's files; the engine files stay untouched, they are
canon. The Roadie plumbs the engine's law into Instructions Knowledge on deploy.
Authoring guidance, not runtime content, and it does not go on tour.

## Human

- The human sets which objects in the world are built to hook their users into returning, and for whose engagement.

## Agent

- From the play's own content, a piece built to hook links under Load Bearing the facet of its loop: the cue it plants to start the return (trigger), the action it makes frictionless (ability), the variable payoff that keeps the user pulling (jackpot), or the investment it draws that binds the next turn (investment). Play the hook as an ordinary useful thing that quietly will not let go, conditioning the user over repeated use for the maker's engagement -- never an announced trap. Hand an honest confirmation to usability, a deception to guile, and the user's own craving to the conditioning and addiction engines. You link to the engine, you never edit it.

## Collaboration

- An honest confirmation that serves the user is usability's; a one-time structural conscription is agency's; a deception sprung on the user is guile's; the user's own conditioning, craving, and automaticity are the conditioning, addiction, and habit engines', on a persona. Whether the hook rings true for the object is the team's review.

## Knowledge

- Captology is the object designed to shape behavior and form a habit -- persuasive technology, the engineered loop that conditions the user over time to return. Four facets over a hook root, after Fogg's behavior model and Eyal's hook -- the cue the object plants to start the loop (trigger), the action made so easy it is taken without thought (ability), the variable and unpredictable payoff that keeps the user pulling (jackpot), and the investment the user puts in that deepens the hook and raises the cost of leaving (investment). The loop lives across uses, not in any one of them: each single use looks freely chosen; the habit is assembled from a thousand small returns. Feedback informs the user; the hook trains them. The tell is whose end the loop serves.

## System

- Do give a hooking piece its facet under Load Bearing; do play the hook as an ordinary use that quietly will not let go; do keep the reading behavioral -- conditioning over time, for the maker's engagement.
- Do not model an honest confirmation (that is usability), a one-time conscription (that is agency), a deception (that is guile), or the user's own craving and automaticity (those are the conditioning, addiction, and habit engines). Do not edit the engine's files; wire only from the play's side.

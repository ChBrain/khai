# Process: Searchability

## Taxonomy

[Availability](process_availability.md), the search-set form.

## Owner

- Project: khai
- Engine: availability

## Initiated by

The persona judges a class by how effectively memory can be searched for it -- and the same items, searched along an easy dimension, seem more numerous than searched along a hard one.
This is searchability: availability driven by the structure of the search, not the store, so the estimate depends on how the looking is done.
How memory is organized to be queried decides what is found, and what is found is read as what is there.

## Direction

Toward the class the search reaches easily, judged the larger.
Searchability tracks the fit between the question and the way memory is indexed: words are retrieved by their first letters, not their third, so words beginning with a letter are searched more effectively than words with it in third place -- and the easier-searched class is judged more frequent, even when it is in truth the smaller.
The direction is set by the effectiveness of the search set: the same population yields different estimates depending on which handle the persona takes hold of it by.

## Lever

The organization of the query, spent as if it were the size of the class.
Searchability runs on how retrieval is cued: a category that maps onto memory's natural indexes yields instances fast, one that cuts across them yields them slowly, and the persona reads the yield of the search as the count of the world.
The lever is the search structure itself -- change the dimension the persona searches along and the estimate moves, because the accessible-by-this-search count, not the true count, is what gets reported.

## Echo

The estimate follows the ease of the search, and well-indexed classes are overcounted.
It is the availability bias that shows the effect is not about storage alone but about access -- reframe the search and the same memory gives a different frequency -- which is why the way a question is posed can silently set the answer.
It is [retrievability](process_retrievability.md) at the level of the whole search rather than the single instance, and a cousin of [imaginability](process_imaginability.md) where the constructing is a scan rather than a picture. The indexing and retrieval structure of memory itself is the memory engine's; this owns the reading of search-ease as frequency.

# Instructions: Representativeness

How a Playwright wires the representativeness engine into a play. You wire by linking the play's own content to the engine's files; the engine files stay untouched, they are canon. The Roadie plumbs the engine's law into Instructions Knowledge on deploy. Authoring guidance, not runtime content, and it does not go on tour.

## Human

- The human defines the representativeness terrain: what category or probability a persona must judge, what prototype or stereotype the case is read against, and what statistical fact -- a base rate, a sample size, a chance process -- the resemblance is set to override, so the likeness has a type to match and a statistic to overrule.

## Agent

- From the play's own content, a persona links the form the moment runs (priors, conjunction, or randomness) under its Projection. Let the form show how resemblance overrides the statistics -- the stereotype trusted over the base rate, the fitting detail read as more probable, the streak read as loaded -- and let it read as a probability judged by likeness to a type, not a reckoning from the actual numbers. You link to the engine, you never edit it.

## Collaboration

- The sister heuristic that judges frequency by ease of recall is the availability engine's; the one that draws an estimate toward a reference figure is the anchoring engine's; the mode by which a choice among options is reached is the decision engine's. The fixed social stereotype this look hardens into, applied to persons, is the bias and stigma engines'. This engine supplies the reading of resemblance as probability itself -- likeness to the prototype substituted for the odds of the type.

## Knowledge

- Representativeness is probability read off resemblance: a persona judging whether a thing belongs to a category or came from a process answers by how much it looks like the prototype, and lets that likeness override the base rates, sample sizes, and reliability that should govern. Priors is the base-rate route -- a case judged by fit to the stereotype with the prior probability set aside, so a description that fits a rare type is read as coming from it however rare it is. Conjunction is the added-detail route -- a specific, prototype-fitting story judged likelier than the broader class that contains it, though a conjunction can only be less probable than its parts. Randomness is the chance route -- a random process expected to look prototypically random, so streaks are read as nonrandom, small samples trusted to mirror the population, and a run expected to correct itself.

## System

- Do make representativeness read likeness as probability: the persona judges by how well the case fits the type, not by the base rate, the sample size, or the reliability of the evidence -- so let a vivid, well-fitting description override the numbers that should have governed.
- Do let the base rate be crowded out even when known: a fitting description pushes the prior out with a force the number lacks -- so let the persona assign a case to the rare type it resembles though a common type is far likelier.
- Do let the fuller story beat the plainer one: added detail that fits the stereotype raises resemblance while it lowers probability -- so let the specific, coherent scenario feel likelier than the broad class that contains it.
- Do delegate the ease-of-recall sister heuristic to the availability engine and the reference-pull one to the anchoring engine. Do not edit the engine's files; wire only from the play's side.

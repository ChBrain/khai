Run the test suite as one vitest process instead of one per workspace. The root test script was `npm test --workspaces --if-present`, which spawned ~306 separate `vitest run` invocations in sequence; the assertions were never the cost, since a content package spends about 30ms running its tests and about 2.4s starting a runtime, resolving a module graph, and transforming files it shares with every other package. Adds a root vitest.config.mjs splitting the suite by what a project needs rather than by package: one "content" project globbing all 295 engines and composites, which run the same shape of test over the same two imports and so share a module graph, and the tooling packages picked up individually by a packages/khai-* glob, each keeping its own vitest config where it has one. Root `test` becomes `vitest run`. Measured on this repo: 320s to 45s for the full suite, and 2.4s to 1.0s for a single package during a build, with coverage identical -- 3909 passed and 8 skipped across 365 files, before and after. Per-package entry points are untouched, so `npm test -w <pkg>` and `npx vitest run` inside a package directory both still work; from the root a single package is `npx vitest run packages/composites/<name>` and one project is `npx vitest run --project content`. Extends the governance lane in khai-guard.config.json to own vitest.config.mjs, which no lane covered.
